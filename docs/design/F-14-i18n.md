# F-14 — i18n (EN/RO) — NOT STARTED

**Status: design note only.**

## Approach when it happens

- Every operator-facing string (report sections, console lines, finding
  descriptions) routes through a `t()` lookup with a message id; the
  Romanian translation lives in a `locales/ro.po` catalogue (gettext —
  stdlib, no new dependency).
- `--lang en|ro` selects the catalogue; `--lang` without a translation
  falls back to English with a notice, never to mixed-language output.
- Finding *descriptions from data sources* (advisory names, CVE texts)
  are NOT translated — they are quotations; only the scanner's own
  framing text is.

## Why it is deferred

It touches every user-visible string (several hundred) with zero
behavioural gain; doing it before the CLI subcommand split (roadmap item
2) would mean re-translating strings the split then moves or renames.
